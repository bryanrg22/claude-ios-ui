# Widget presentation and extension

The separate `ClaudeWidgets` Swift package product contains immutable presentation data, strict local deep-link routes, and SwiftUI widget content. It does not depend on `ClaudeUI`, UIKit application APIs, accounts, hardware, or networking. `WidgetDemo/` is a genuine WidgetKit executable extension embedded in `ClaudeUIDemo.app/PlugIns/`; the checked-in XcodeGen specification recreates both targets.

The three observed gallery variants are Quick Actions small and medium, and Code shortcuts small. Their dark charcoal container, black top pill, orange asterisk, camera/voice glyphs, Code action and Dispatch remote glyph follow the captured references. The Code variant exposes a top Code pill and lower plus/search circles. The reused asterisk has the same provenance limitations documented in THIRD_PARTY.md. The custom five-bar voice and remote outlines are original approximations; SF Symbols supply other icons. Gallery perspective/tilt is system presentation, not a rotation applied to widget content. Light/tinted appearances were not captured and are not claimed as matched.

The extension uses `StaticConfiguration`, `TimelineProvider`, `.supportedFamilies`, and `.containerBackground(for: .widget)`. Apple documents these in [Creating a widget extension](https://developer.apple.com/documentation/WidgetKit/Creating-a-Widget-Extension) and [Displaying the right widget background](https://developer.apple.com/documentation/widgetkit/displaying-the-right-widget-background). Native `Link` controls and a default `.widgetURL` provide local destinations; see [Linking to specific app scenes](https://developer.apple.com/documentation/widgetkit/linking-to-specific-app-scenes-from-your-widget-or-live-activity). Older creation-guide wording limits multiple links to medium and larger, while the current scene-linking guidance includes small; the three separate small-widget links were empirically verified on the iOS 27 simulator.

The demo registers `claude-ui-demo://widget/<destination>` and validates every URL component and its canonical spelling. Chat/Voice start a local session, Camera opens the existing synthetic camera presentation, Code opens the session list, Dispatch opens the injected offline fixture, and New Code session opens its draft. Search Code opens Code and emits its existing search intent; its uncaptured search destination is not invented. No task is submitted by a widget, and no microphone or camera permission is requested. Hosts may replace these local demo routes with their own handlers.

Run the app with `--widgets` for a side-by-side interactive preview. This is a demo inspection surface and is not an app screenshot reference. The static timeline requires no shared container or reload loop. The demo asks WidgetCenter to reload once on launch so local rebuilds refresh cached snapshots; no network data is fetched. The content and links are injectable/reusable through `ClaudeWidgetPresentation`, `ClaudeWidgetContent` and `ClaudeWidgetView`.

## Validation

All 55 state tests pass in `/private/tmp/claude-ui-widget-final-unit.log`. The strict-route suite caught and fixed Foundation's normalization of a trailing slash. The seven in-app preview links and three installed small-widget links passed in `/private/tmp/claude-ui-widget-native-links.xcresult` (2 tests, 66.2 seconds). Native controls opened the synthetic camera, inline voice, and ordinary chat independently. A second installed-link run passed in `/private/tmp/claude-ui-widget-gallery-final.xcresult`; that bundle's separate gallery setup test failed an overly narrow app-icon frame lookup, corrected before the final gallery run.

The native gallery tests are deliberately opt-in because they interact with the simulator Home Screen. Prefix `xcodebuild ... test` with `TEST_RUNNER_CLAUDE_NATIVE_WIDGET_TESTS=1` and select `testWidgetNativeGalleryVariants` to capture all three registered pages. `testWidgetInstalledSmallLinks` additionally requires the small Quick Actions widget already installed. The default suite skips these two tests; the in-app preview test runs normally. On the tested iOS 27 runtime, SpringBoard can take 60 seconds to report animation completion after long presses. Test captures wait for actual page-indicator changes rather than assuming a swipe advanced a page.

`docs/fidelity/screenshots/widgets-preview.png` is a synthetic in-app inspection surface. `widget-native-installed.png` shows the actual embedded extension on the simulator Home Screen after returning from all three destinations. Widget corners, rim and Home Screen material are rendered by iOS. The demo app icon is still the Xcode placeholder; launcher brand artwork has not been supplied. Glyphs and dark styling are approximations constrained by the captured references, not an assertion of pixel identity across appearances, wallpaper, OS versions or Dynamic Type.

The corrected native gallery flow passed in `/private/tmp/claude-ui-widget-gallery-verified.xcresult` (1 test, 145.8 seconds), asserting all three page values and capturing each actual registered variant. Both initial test failures were harness selectors: an icon-width filter and the underlying Home Screen page indicator. The final selector uses the gallery indicator’s observed wide frame. All three exported screenshots were visually inspected: `widget-native-quick-small.png`, `widget-native-quick-medium.png`, and `widget-native-code-small.png`.

Final generic iOS Simulator build passed in `/private/tmp/claude-ui-widget-generic-build.log`; Xcode validated the embedded `ClaudeDemoWidgets.appex`, and `lipo -info` confirmed arm64 and x86_64. This checkpoint has 55 passing state tests and 20 unique UI flows exercised across scoped runs (18 app flows and 2 opt-in native widget flows); it is not a claim that all 20 were rerun in a single final suite.
