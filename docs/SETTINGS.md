# Settings reference coverage

The October 8 captures now inform Settings root, Profile/Instructions, Notifications, Time & focus selectors, Privacy, Usage, Billing’s website-subscription notice, Shared links, Claude Code appearance preferences, Capabilities, Memory files, and Settings connector/tool-policy screens, All tools, connector browsing/filtering, and the custom connector draft. All public account, transaction, conversation, connector and memory fixtures are fictional. This is a UI-only presentation package, not whole-app parity or an account integration.

Remaining gaps include the avatar catalog, account switching/add-account/gift destinations, selected quiet-day behavior, Settings Voice/Permissions, connector authentication/authorization and submitted-result/error states. Light subpage variants are adaptive rather than separately captured app references. Proprietary fonts/logos, exact symbol metrics, and announcement motion remain qualified limitations. Historical checkpoints below retain their original counts; the latest bounded checkpoint appears at the end.

`ClaudeSettingsState` owns the injected account summary and committed profile. Opening Profile creates an independent draft. Back or dismissal abandons that draft. `submitProfile` creates a UUID-tagged `pendingProfile`; the host must call `acknowledgeProfile(requestID:profile:)` to commit. Cancellation, navigation away, subsequent editing, and a new session invalidate pending acknowledgements. `rejectProfile(requestID:)` clears a matching failed request while retaining the draft for retry; the host owns error presentation. The demo acknowledges locally without a network call. The real app's save response, validation errors, and save-navigation behavior have not been captured.

`ClaudeSettingsAction` exposes photo editing, account deletion, logout, guidelines, and each destination as typed intents. These do not perform account operations. `ClaudeSettingsView` accepts optional host destination content. The captured info button opens a native menu with injected version text and typed Usage Policy, Consumer Terms, Privacy Policy, Licenses, and Help & Support actions. Edit photo opens the captured Choose an avatar / View photo library / Take a photo menu; destination handling is still host-owned. Captured subpages are implemented as described below; uncaptured destinations remain host seams, with no speculative account or permission toggles. Profile initials are independently host-provided, so name changes do not infer an avatar update.

The observed haptic switch changes local preference state only; device haptics are not implemented. Appearance continues to use the shared session preference. Both preferences survive a new conversation. Instructions opens a nested large-sheet multiline editor from the captured reference. It has a separate draft: cancel discards the nested edit, and apply returns it to the profile draft. Final persistence still requires the profile host acknowledgement. The real app’s apply/save outcome and long-content maximum are unobserved. SF Symbol substitutions, native material rendering, and typography remain approximations.

Apple's [model-data guidance](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) informs the single state owner and bindings. The observed screens use local route state; the host may supply deeper views without replacing the settings shell.

## Usage, Billing, and Shared links

Unknown/nonfinite percentages stay distinct from zero; finite values are bounded to 0–100. They never alter balances or consent and never fetch an account. The help destination observed on the phone is a native browser; the host supplies its URL and presentation. The demo uses fictional amounts and dates. The dark progress-bar track was sampled near RGB 10/30/64 from the captured reference. Light styling is an adaptive implementation.

Billing accepts `ClaudeBillingState` with host plan, subscription origin, and optional management URL. The package does not integrate StoreKit, restore purchases, or change a plan. Other origins remain host-handled because their destination screens were not captured. Closing Settings clears the transient notice.

Invalid snapshot identifiers are ignored, removal of selected host data returns the presentation to the list, and closing/new-session clears selection while retaining host records. ## Capabilities and Memory files

`ClaudeCapabilitiesState` holds host-owned values for Artifacts, Inline visualizations, Code execution and file creation, switching a flagged message to another model, searching chats, generating memory, and including sensitive topics. Each value supplies enabled/editable state and an optional dependency explanation. The demo injects the captured disabled-on Artifacts state with “Required by code execution”; no dependency rule or consent truth is inferred inside the reducer. Taps emit `.capability(.requestEnabled(...))` without changing these values. Help links carry host URLs, and the package does not call any model, execute code, access old chats, or enable memory.

Memory files reproduces the observed grouped You/Topics list, update subtitles, SF-style Markdown detail, floating instruction composer, trash action, and native Cancel/Delete notice. All file titles, summaries, content and update labels are injectable; the demo uses fictional records. The composer emits `.memory(.submitInstruction(fileID:text:))` and retains its draft until the host handles it. List and individual-file drafts are independent, survive detail/list navigation, and clear when Settings closes. Composer growth and submitted-result presentation were not captured; the current local growth limit is provisional.

Confirming the native delete notice creates `memoryFiles.pendingDeletion` with a UUID and file identifier; it does not remove anything. Hosts call `acknowledgeDeletion(requestID:)` after success or `rejectDeletion(requestID:)` after failure. Only a matching current request can remove a record, and navigation/new-session invalidates pending requests. Cancellation, repeated confirmation, unknown IDs, host record removal, retry, and stale acknowledgements have pure tests. No account deletion request or persistence layer is shipped. The demo deliberately leaves the file present after a confirmed request.

## Settings connectors

The Settings connector routes reuse `CodeConnector`, `CodeConnectorTool`, and `CodeToolPermission` from the Code UI. `ClaudeSettingsConnectorState` adds navigation while leaving connection, discovery and permission truth host-owned. The captured root discovery card, connected tool counts, available Connect rows, connector All tools summary, per-tool list, and individual policy page are rendered. Long tool names place their status below the title as observed. Tool descriptions are host-supplied text; they are never interpreted as instructions.

At the first connector checkpoint, Catalog and All tools were host hooks. Later reference captures enabled the local destinations described below. Discovery, Connect and policy changes remain typed host requests; no service connection or permission change occurs. `ClaudeSettingsConnectorsView` accepts caller-supplied artwork through `iconContent`; default SF Symbols and fictional demo service names do not claim brand-logo parity. Invalid/removed host records cannot leave a stale policy page visible, and closing Settings clears connector navigation while retaining host data.

The Memory editor also supports `.memory(.replaceDraft(text))` for an explicit host replacement or clear. This increments an editor revision and recreates the native input so a focused edit buffer cannot hide the new host value. Ordinary `.editDraft` callbacks preserve the active buffer. The demo’s `--memory-clear-after-submit` fixture exercises this acknowledgement behavior without modifying a real memory service.
