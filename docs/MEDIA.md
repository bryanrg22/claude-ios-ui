# Image presentation contract

`ClaudeMedia` holds an ID, file name, accessibility description and aspect ratio. `SessionState.media.recent` and `.draft` are host-injected metadata arrays. `ClaudeSessionView(mediaContent:)` asks the host to render each item for `.thumbnail`, `.message` or `.viewer`; the package does not load URLs, read the photo library, or request hardware permissions. The default is a neutral image placeholder. Supply clipped fill content for thumbnails and fitted content for the viewer. The demo supplies original SwiftUI landscape illustrations.

The observed Recent strip supports selection/deselection and a count-aware Attach button. Closing it discards pending selection, while confirmed draft items remain. Draft removal, photo-only sends, message editing/cancellation, and new-session reset are local state transitions. Photos emits `.media(.requestPhotos)` for a host to present a picker. A later native photo-library capture showed Photos/Collections, up to 20 items, and a Show Selected footer; the reusable shell intentionally leaves this permission-bearing surface to the host’s PhotosPicker integration. Apple’s [PhotosPicker](https://developer.apple.com/documentation/photokit/photospicker) is the native integration point when a host chooses to implement that behavior.

Sent photos appear separately above the user text bubble. Their native context menu contains the observed **Copy file name** action. The black full-screen viewer retains the system status bar; tapping the image hides/shows the toolbar without moving the image. Close dismisses it. Edit and Share emit typed `.media(.edit(item))` and `.media(.share(item))` intents; their destination screens are unobserved. Copy file name emits a host intent, and the demo writes only the fictional file name to the clipboard.

Reference geometry: recent tiles 100pt; composer tiles 80pt with a 24pt removal control; the observed sent portrait fit is approximately 194×200pt; viewer uses the available width and aspect-fit bounds. Other source aspect ratios use defensive fitting, but panorama, multiple-photo message layout, pinch zoom, upload and error/loading treatments remain unverified. Invalid or nonfinite host aspect ratios fall back to 1. The reducer handles only local metadata; host uploads and results belong outside this package.

## Video attachment checkpoint

A subsequent real nine-second MP4 established a distinct route: an 80pt composer poster with no duration, then a right-aligned 140pt square file card with a pale file placeholder, middle-truncated filename stem and MP4 footer. Long press exposes only Copy file name. Tapping opens a large sheet beneath the status bar, with a material header, Close, filename and an ellipsis menu containing only Download. Tapping the movie did not reveal transport controls or hide the header. Playback began automatically; the final frame remained visible across several captures, and playback restarted when the viewer was reopened and after dismissing the native Download share sheet. Those observations do not establish a universal loop/end policy. Buttons visible *inside* the reference’s recorded Dot/Control Center screen are movie content, not player controls.

`ClaudeMedia.kind` distinguishes `.image` and `.video`; existing initializers default to image. Video uses `.videoViewer` in the host's `mediaContent` closure, with `.videoViewerAppeared(item)` / `.videoViewerDisappeared(item)` lifecycle intents. The shell does not create an AVPlayer, load a file or URL, download media, loop playback, or invent image Edit/Share controls. `.download(item)` is a host intent. A later capture showed Download opening the system share sheet; hosts may resolve their file URL and present native UIActivityViewController, without recreating suggested contacts or service extensions.

Only the demo uses Apple's [AVPlayerLayer](https://developer.apple.com/documentation/avfoundation/avplayerlayer) with a bundled, original generated H.264 sample (`Demo/Resources/Garden-Motion.mp4`, 240×426, silent, exactly 9 seconds, approximately 16 KB). It autoplays once, pauses at the end, and releases playback on dismissal. Reopening creates a fresh player. Launch `--video` to start with the sample poster in the draft. The sample’s pause-at-end policy is a deterministic demo choice; actual playback lifecycle remains host-owned. The sample is an abstract blue scene with a moving pale circle; no private screen recording or source app content is included. Actual network uploads, playback errors, codec compatibility beyond this sample, audio policy and downloading/sharing remain host responsibilities.
